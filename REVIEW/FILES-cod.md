# Repository Catalog and Filesystem Tree

This document catalogs the repository structure, with a filesystem tree and concise descriptions for folders and files. For large homogeneous data directories, individual files follow a consistent pattern described below.

## Summary

- Purpose: Curated collection of UDHR (Universal Declaration of Human Rights) translations in XML, plus tools and merged datasets for indexing, transliteration, and cross-referencing with sources like Omniglot.
- Primary data: `data/udhr/*.xml` (490 files), `data/status/*.xml` (576 files), transliterations in `data/udhr-translit/*.xml` (70 files).
- Processing tools: Python utilities in `tools/` for indexing, fetching, transliteration, and merging metadata.
- Derived data: YAML aggregations in `merged/`.

## Filesystem Tree (top-level)

```
.
```

## Folder Catalog

### data/

- Description: Root directory for all UDHR-related XML data, including canonical texts, status metadata, curated subsets, and transliterations.

Subfolders:

- data/udhr/
  - Description: Core UDHR translations in XML, plus schema and index.
  - Key files:
    - index.xml: Manifest of translations in this folder.
    - schema.rng, schema.rnc: RELAX NG schemas defining XML structure.
    - template.xml: Example XML template for new translations.
    - udhr_*.xml: Individual UDHR translations. Pattern details:
      - udhr_LANG.xml (e.g., `udhr_eng.xml`, `udhr_fra.xml`): Translation keyed by ISO639-3 or language tag variants.
      - udhr_LANG_SCRIPT.xml (e.g., `udhr_bos_cyrl.xml`, `udhr_azj_latn.xml`): Translation in a specific script.
      - udhr_NUM.xml (e.g., `udhr_007.xml`): Special-numbered entries retained for compatibility.
  - Purpose: Authoritative source texts for downstream processing and research.

- data/status/
  - Description: Status/metadata XML files per language or special set.
  - Files: `status_*.xml` where the suffix is either a number (historical index) or a language/script code.
  - Purpose: Track availability, processing stage, or metadata nuances for translations.

- data/retired/
  - Description: Deprecated status or UDHR files kept for reference.
  - Files include:
    - status_fuc.xml, status_prq.xml: Retired status definitions.
    - udhr_fuc.xml, udhr_fum.xml, udhr_prq.xml, udhr_tam.xml: Retired UDHR translations.
  - Purpose: Preserve legacy or superseded entries without mixing into active sets.

- data/udhr-manual/
  - Description: Manually curated or special-case translations and a local index.
  - Key files:
    - index.xml: Manifest for this curated set (generated by `tools/make_index_xml.py`).
    - status_egy_egyp.xml: Status entry for Egyptian (Egyptian Hieroglyphs) context.
    - udhr_cmn_nshu.xml: Chinese (Nüshu) entry.
    - udhr_egy_egyp.xml: Egyptian (Egyptian Hieroglyphs) entry.
    - udhr_eng_brai.xml: English in Braille.
    - udhr_eng_dsrt.xml: English in Deseret.
    - udhr_eng_shaw.xml: English in Shavian.
    - udhr_hmn_hmng.xml, udhr_hmn_hmnp.xml: Hmong in Hmong script variants.
    - udhr_men_mend.xml: Mende in Mende Kikakui.
    - udhr_rej_rjng.xml: Rejang in Rejang.
    - udhr_rhg_rohg.xml: Rohingya in Hanifi Rohingya.
    - udhr_smp_samr.xml: Samaritan in Samaritan.
    - udhr_syl_sylo.xml: Sylheti in Syloti Nagri.
  - Purpose: Track items requiring manual handling or special validation.

- data/udhr-translit/
  - Description: Transliteration variants and indices for cross-script representations.
  - Key files:
    - index.xml: Global manifest of transliteration entries.
    - index_aksharamukha.xml: Index for entries produced via Aksharamukha library.
    - index_gimeltra.xml: Index for entries produced via Gimeltra transliteration.
    - udhr_aii_*.xml: Classical/Aramaic varieties in numerous historic scripts (e.g., armi, elym, sogd, ugar...).
    - udhr_san_*.xml: Sanskrit transliterations into many Indic and historic scripts (e.g., avst, bhks, dogr, khar, sidd...).
    - udhr_mar_modi.xml: Marathi in Modi script.
  - Purpose: Enable typography testing, script support validation, and comparative cross-script analysis.

### merged/

- Description: Derived YAML datasets merging UDHR content with external sources such as Omniglot and official indexes.
- Files:
  - udhr-art1-omniglot.yaml (and numbered variants 2–8): Aggregated Article 1 entries enriched with Omniglot metadata across versions.
  - udhr-art1-omniglot7-lines.txt: Line-oriented intermediate for Omniglot v7.
  - udhr-omniglot.yaml: Broader Omniglot mapping data.
  - udhr-art1-omniglot-orig.yaml: Original import snapshot.
  - test.py: Lightweight check over merged YAML data.
- Purpose: Staging area for composite datasets used in research, visualization, or further processing.

### tools/

- Description: Python tooling and configs to fetch, index, transliterate, and merge UDHR datasets.
- Files and purpose:
  - aksharamukha-scripts.yml: Configuration of scripts processed via Aksharamukha.
  - aksharamukha_scripts.py: Script utilities listing or managing Aksharamukha script sets.
  - aksharamukha_scripts_sanskrit.py: Sanskrit-centric script configuration.
  - aksharamukha_transliterate.py: Batch transliteration pipeline using Aksharamukha.
  - edit_omniglot.py: Manual editing helpers for Omniglot-derived data.
  - gimeltra_transliterate.py: Transliteration pipeline using Gimeltra.
  - install.sh: Helper shell installer for Python deps (legacy).
  - make_index_xml.py: Generate `data/udhr-manual/index.xml` from UDHR XMLs.
  - requirements.txt: Python dependencies for tooling (e.g., lxml, langcodes).
  - scripts.yaml: Tool run configurations.
  - shavian/dave.dict: Shavian mapping dictionary.
  - shavian/shaw.py: Shavian-related processing script.
  - shavian/udhr_eng.html: Shavian UDHR HTML sample.
  - test.py: Minimal test or data check for tools.
  - udhr-art1-omniglot.yaml, udhr-omniglot-codes.yaml, udhr-omniglot.yaml: Omniglot mapping datasets for tools.
  - udhr_art1_aksharamukha.yaml: Article 1 transliterations via Aksharamukha.
  - udhr_art1_official.yaml: Article 1 data parsed from official UDHR sources.
  - udhr_art1_r12a.yaml: Article 1 data parsed from r12a.github.io sources.
  - update_from_official_udhr.py: Fetch/parse official UDHR sources into structured YAML.
  - update_langnames_in_merged.py: Normalize/update language names in merged YAML.
  - update_omniglot.py: Refresh Omniglot-derived mappings.
- Purpose: Provide reproducible pipelines to maintain and extend the dataset.

## Pattern-Based File Descriptions for Large Sets

To keep this catalog practical while complete in purpose, large homogeneous directories are described by pattern:

- data/udhr/udhr_*.xml: One XML per language/script variant of the UDHR. Each file contains metadata (xml:lang, iso639-3, iso15924, dir, key, n), preamble, and 30 articles, optionally with ordered lists.
- data/status/status_*.xml: Status/metadata entries, keyed either by historical numeric ID or language/script identifiers. Use to track availability, validation status, or curation notes.
- data/udhr-translit/udhr_LANG_*.xml: UDHR text transliterated into the specified script (suffix), primarily for Sanskrit and Aramaic families, plus selected languages.

If you need an explicit per-file listing for auditing, generate with:

```
find . -type f | sort
```

## Notes

- Use `tools/make_index_xml.py` when updating files in `data/udhr-manual/`.
- Validate new UDHR XMLs against `data/udhr/schema.rng`.
- See `README.md` for usage examples and data structure details.
